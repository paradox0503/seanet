# 基于 Loss 的累计式课程学习设计

## 目标

用模型首次前向计算得到的 batch 总 loss 代替人工分段方差，作为课程学习的难度指标。首次评估只负责难度排序，不反向传播、不更新模型参数，也不占用配置中的正式训练轮数。正式训练从简单 batch 开始，并逐阶段累计加入更难的 batch。

## 范围

- 仅修改预训练模式下 `linearlycombine` 训练流程的课程选择逻辑。
- 保留现有 100 轮默认结构：前 80 轮执行 8 个课程阶段，每阶段 10 轮；80 轮后从全部训练 batch 中随机采样。
- 保持每个正式训练轮次选取的 batch 数量不变，避免累计候选池导致单轮计算量持续增加。
- 不改变模型、优化器、验证、检查点和训练总 loss 的定义。

## 难度评估

在正式训练循环开始前遍历 `train_total_loader` 一次：

1. 将模型临时切换到评估模式，并在 `torch.no_grad()` 下计算。
2. 对每个原始 batch 独立生成数据库序列和两个查询序列的随机排列，与正式训练的数据构造方式保持一致。
3. 使用正式训练的总 loss：`trans_error + orth_term + recons_term + return_l2`。
4. 保存 `(loss, 原始 batch 索引)`，按 loss 从小到大排序；loss 越小表示越简单。
5. 评估结束后恢复模型此前的 train/eval 状态。

该阶段不调用 `optimizer.zero_grad()`、`backward()`、`optimizer.step()`、学习率调整或权重衰减调整，`self.epoch` 保持不变。

## 累计课程调度

排序后的 batch 均分为 8 个连续难度区间。第 `k` 个课程阶段的候选池包含前 `k` 个区间：

- 第 1 阶段：最简单的 `1/8`；
- 第 2 阶段：最简单的 `2/8`；
- 依次扩大；
- 第 8 阶段：全部 batch。

每轮仍抽取 `max(1, 总 batch 数 // 10)` 个 batch。候选池小于该数量时使用候选池全部 batch；否则从累计候选池中无放回随机抽取。第 80 轮以后继续保持现有策略，从全部 batch 中随机抽取相同数量。

区间边界按比例计算，最后一个区间必须覆盖余数，确保所有 batch 最终都能进入候选池。数据集来源信息始终使用原始 batch 索引查询，避免排序后索引和原始索引混用。

## 日志和异常

- 难度评估完成后输出 batch 数、最小 loss、最大 loss 和每轮抽取数量。
- 每个阶段首次进入时输出当前累计候选池覆盖比例。
- 如果训练集为空，直接抛出明确异常。
- 如果预训练使用的不是 `linearlycombine`，抛出明确异常，避免用不同训练目标生成不一致的难度排序。

## 验证约束

用户已说明本地没有运行环境，因此本次不执行训练、单元测试或语法运行检查。修改完成后仅进行静态复核：检查 diff、索引映射、梯度更新边界、epoch 计数以及 loss 公式与正式训练的一致性。
